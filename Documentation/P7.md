### 数据与兼容性

- 继续复用现有加密 manifest 和释放操作日志，无新增后端 API 或数据库迁移。只增加可选的风险确认版本字段，旧设置缺少该字段仍能解码。
- 手动刷新依旧按大小阈值、普通文件重复组及媒体候选选择上传；不因扫描器为小文件计算 SHA 就上传全部小文件。跨页重复内容复用已有归档。上传结束按本次处理计数报告，不用全历史绑定数量冒充本次结果。
- 手动重新扫描保留已隔离/释放记录的分页展示，但这些记录不会上传。没有当前扫描时也能分页读取归档索引；恢复中心仍独立工作。
- 扫描失败保留上一轮发布结果；停止手动任务或切换目录取消旧工作。后台分页使用请求代次，旧目录或旧筛选结果不能覆盖新页面。
- 云端检查失败不会用删除云对象来“回滚”。云端已上传、但本地提交失败时保留原件，后续继续走现有对象索引去重。原有隔离/最终删除日志、中断对账、SHA 检查和排他写入保护保留。
- HEAD 的 SHA 是上传元数据，不是重新下载计算完整内容 SHA。P7 不把它描述为额外恢复测试，也不改变 P4 不自动下载额外恢复副本的既定策略。恢复仍校验下载文件与写回文件的完整 SHA。
- 原路径写入前的云端检查只能证明检查时可读，不能保证服务未来永远可用。索引丢失时不承诺自动重建微信原路径。

## 分发与更新操作

以下是原有 Developer ID 公证分发流程。2026-09-09 用户另外授权了未公证公开测试渠道，官网现已上线；详情见文末及 [官网发布记录](../Website/README.md)。该渠道不代表下面的真实公证验收已通过。

本机先运行 `Scripts/package-beta.sh prepare`：生成 `.build/beta/prepare/WeVault.zip` 和 SHA-256 文件。该包是双架构工程预览，临时签名，没有公证；目录中保留 `NOT-FOR-DISTRIBUTION.txt`。原有运行中的开发应用不被这个命令替换。

真实分发之前，由维护者在本机提供以下配置，敏感公证凭据保存到 notarytool Keychain profile，不写入仓库或命令日志：

| 配置 | 含义 |
| --- | --- |
| `WEVAULT_VERSION` / `WEVAULT_BUILD` | 三段版本号与单调递增正整数 build |
| `WEVAULT_FEEDBACK_EMAIL` | 实际接收反馈的邮箱，不能使用示例地址 |
| `WEVAULT_UPDATE_FEED_URL` | 实际部署的 HTTPS 版本 JSON 地址 |
| `WEVAULT_SIGN_IDENTITY` | 本机有效的 `Developer ID Application: …` 签名身份 |
| `WEVAULT_NOTARY_PROFILE` | 已保存的 notarytool Keychain profile 名称 |

1. `Scripts/package-beta.sh preflight` 检查本地配置、证书和工具。它不联网验证 profile；提交时由 notarytool 验证。缺项时直接失败，没有降级为临时签名分发的路径。
2. `Scripts/package-beta.sh notarize` 构建双架构应用，使用 Developer ID、Hardened Runtime 和时间戳签名，再提交 Apple 公证。只有 `Accepted`、装订、签名校验和 `spctl` 全部成功，才重新打包装订后的应用并移除不可分发标志。失败产物不能分发。每次构建开始前即写入不可分发标记，配置、构建或校验和生成失败也不会遗留看似本次通过的旧产物；校验和生成成功后才移除标记。5 项 Python 测试包含这些失败路径与完整成功路径的工具替身测试，不调用真实签名或 Apple 服务。
3. 在干净测试环境完成 Gatekeeper 首次启动、恢复链接、Keychain 解锁、旧索引打开和保留暂停状态的升级验收后，上传经验证的 ZIP 与 SHA-256 到下载站点。公证流程不自动发布；另行授权的官网部署步骤见 Website/README.md。
4. 使用 `Scripts/write-update-feed.py --app <应用路径> --download-url <HTTPS下载页面> --notes <说明文件> --output <新JSON路径>` 从同一应用生成版本源。生成器拒绝覆盖既有文件。最后更新 HTTPS 版本源，避免用户先收到一个尚不可下载的版本。

版本 JSON 包含 `version`、`build`、`minimumSystemVersion`、`downloadURL` 和 `releaseNotes`。客户端只接受 HTTPS、最大 64 KiB、有效 build/系统版本的响应；拒绝错误状态、不安全下载地址、过大响应和损坏 JSON。仅在用户点击“检查新版本”时请求版本源，无周期遥测或自动安装。构建号不更新或降级时不提示安装。

升级失败时保留旧应用与原始索引，先恢复运行同版本或兼容版本；禁止删除钥匙串、重建空 manifest 或清除隔离副本来解决启动问题。P7 没有索引 schema 变更，但仍需验证从开发临时签名迁移到 Developer ID 时的系统 Keychain 授权。

签名流程依据 [Apple 公证要求](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)及 [自定义公证流程](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)。
