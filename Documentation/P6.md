## 操作范围与证据来源

- 三个样本均由用户明确定位；恢复前保存独立备份，并验证大小和完整 SHA-256。媒体同时保存微信导出基线。
- 真实云端操作复用当前 `ManagedAccount`、`ManagedCloudArchiveService`、`CloudRestoreService` 和生产加密 manifest。临时单样本运行器每次只输入一个文件；没有点击真实账号的批量上传按钮，也没有把服务层运行记作批量 GUI 验收。
- 隔离使用当前 `LocalReleaseService.isolate`，保留 quarantine，不执行到期最终删除。恢复使用真实云端下载并校验，再写回原路径；正常恢复流程会清理匹配的 quarantine 副本，独立实验备份继续保留。
- 微信自绘页面的工具点击返回 `AXError.notImplemented`，因此查看、播放、放大、保存和清晰度由用户操作与反馈；文件字节、媒体参数、云端下载、原路径及保留层由工具校验。两种证据不混淆。
- 私有证据保存在 `Lab/P6/Networks-PDF/` 和 `Lab/P6/Media/{IMAGE-01,VIDEO-01}/`；导出文件在桌面 `WeVault-P6/01-恢复前`、`02-归档后`、`03-恢复后`。上述目录及 `.build/p6-preflight/` 运行器不提交 Git，真实路径、会话、照片和 binding 仅保留在私有证据中。

## PDF-01：普通文件与恢复链接

原 PDF 为 1,064,652 bytes。备份、真实云端独立下载和恢复后原路径文件的完整 SHA 一致。用户确认从微信打开的是替代 PDF，恢复后再次确认打开的是原文件。

最初暴露两类链接问题：

1. WPS 将 PDF 中的 `wevault://` 自定义 scheme 当作本地文件。不同斜杠形式同样失败；不能通过放宽客户端 URL 校验解决。
2. Chrome 中实际可见的旧复制链接为 `wevault://restore/binding%02<64位十六进制>`，前缀连字符变成 U+0002。原 PDF 的编号和链接还存在换行。

修复与验证：

- 新 PDF 保留应用直达按钮，增加 HTTPS 浏览器恢复入口；编号和 URL 独立成行，使用等宽字体。Office 已验收的原按钮不变。
- `/restore`、`/restore.js` 已部署到现有 API 服务。编号只放在 URL fragment，网页不请求索引、认证或文件，不自动恢复；提供打开应用及复制编号两种操作。部署前保存回滚副本，只重启 WeVault 服务，线上验收脚本通过。
- 客户端仅兼容 `binding` 前缀后这一固定位置的 `%02` 变换，随后执行完整 ID 校验。粘贴入口兼容 PDF 换行及精确域名的浏览器恢复链接；其他编码、权限、额外路径及未知参数仍拒绝。
- 用户确认 WPS 新按钮打开恢复网页；工具确认网页打开正确原生恢复记录。旧 `%02` 链接在真实恢复中心也可定位。系统钥匙串授权由用户在本机处理。

旧占位文件不会被自动重写，新模板从下次生成开始生效。WPS 原自定义 scheme 按钮仍有兼容性限制；通过浏览器入口或归档编号恢复。此结果不改变同名过期对照消息。

IMAGE-01 复用了历史 OLD-H-122 样本。其高清层在先前研究后留在实验隔离区，本轮已从经过 SHA 校验的历史备份恢复基线，采用排他创建，没有覆盖现有文件。用户打开图片后，微信重新生成精确对应的气泡缓存；该缓存另行备份。正式扫描器实扫确认该家族关联与本轮使用的路径一致，补足缓存关联的真实样本证据。

两个样本的最后一步均要求退出重开微信并重新保存；用户随后反馈“清晰了”，两个新的导出文件均已收到并校验。冷启动过程没有自动录像，不单独声称对所有重启/断网条件完成了验证。

视频普通版与 Raw 分辨率相同，编码、码率及大小不同。本轮通过原始字节恢复及实际导出匹配确认 Raw 能力恢复，不把文件变大等同于提升分辨率，也不声称它是微信发送前的原始拍摄文件。

## 修复、规则与回归

- 手动扫描此前把复制 tombstone 再次 hash 并加入重复组；现在不可归档占位不参与普通文件 hash、重复分组或大文件候选。批次扫描保留疑似转发风险提示。
- 图片在 attach 中缺少气泡/缩略层时，只补查同账号、月份、resource ID、prefix 的精确缓存气泡路径；不枚举或上传整个 cache，拒绝符号链接。本轮真实扫描器确认 IMAGE-01 和 VIDEO-01 家族都与操作路径一致。
- 图片只隔离高清层，视频只隔离 Raw 层；普通层和辅助层保持字节一致。不能承诺微信会自动补回旧高质量层；用户需要高质量导出时先通过 WeVault 恢复。
- 本轮高层移走后的模糊与普通版导出是预期降级，须在 UI 中解释。移除详情页中容易与正式路线图冲突的旧“阶段 5/6/7”编号，保留具体释放、保留与恢复说明。
- 110 项 Swift 回归测试、Debug 编译与 Release 构建通过。链接修复时的 9 项服务端测试及 TypeScript 构建通过，线上 staging 验收脚本通过；本次媒体轮没有修改服务端。
- 新测试覆盖复制占位、缓存精确关联、跨账号/月/resource/prefix 不串联、符号链接拒绝、旧链接兼容与非法链接拒绝。网络、凭证、校验失败、目标冲突及中断恢复的隔离回归沿用 P4/P5 测试；未在真实个人文件上注入破坏性故障。
